How the Internet Works — From a 5-Year-Old to an Engineer

This note explains the internet in simple language first, then introduces the real technical terms and removes the simplification gradually. The goal is to understand not only names like DNS or TCP, but also what actually happens inside AWS, browsers, APIs, routers, CDNs, and modern web stacks.

Big picture

When you type https://www.youtube.com and press Enter, a lot happens: DNS resolves the domain, routers move packets, TLS secures the connection, HTTP sends the request, and the server returns the response. The internet is a giant system built from addresses, protocols, and routes.

Core idea: the internet is not one giant machine; it is a connected system of devices, routes, and protocols.

Level 1 — Imagine the internet is a huge postal system

Suppose you want to send a toy to your friend living at a specific address in another city. You need an address, a way to travel, a vehicle, a way to split the package when necessary, and a way to ensure it arrives correctly. The internet works similarly.

Instead of houses, there are IP addresses. Instead of roads, there are network links. Instead of postal vehicles, there are packets.

Computers ask: “What IP address belongs to youtube.com?” That is where DNS comes in.

Level 2 — The most important word: packet

You do not normally send one giant message as a single block. Instead, information is broken into smaller pieces called packets. Each packet includes metadata such as source, destination, protocol information, payload, and sequence control information. 

┌─────────────────────────────┐
│ Source IP                   │
│ Destination IP              │
│ Protocol                    │
│ Port                        │
│ Sequence / control info     │
│                             │
│        PAYLOAD              │
│        actual data          │
└─────────────────────────────┘

The internet moves packets independently. They travel through different routes and are later reassembled at the destination. The packet approach is one of the central ideas behind modern networking.

Level 3 — Your device

Your laptop may have a private IP such as 192.168.1.10. Your phone might have 192.168.1.11. These are usually private IP addresses inside your home or office network. Your router may have 192.168.1.1.

But the outside world does not usually see your laptop directly. A router performs NAT (Network Address Translation): it translates the private IP to a public IP used on the internet. 

Laptop
192.168.1.10
      ↓
Router
      ↓
Public IP
49.xxx.xxx.xxx
      ↓
Internet

IP vs MAC

IP is a logical network address. MAC is a hardware-level address for the local network interface. Example: 

IP:  192.168.1.10
MAC: A4:5E:60:12:AB:91

IP identifies the network location; MAC identifies the network card on the local segment.

Level 4 — Wi‑Fi

Your laptop connects to the router using Wi‑Fi or Ethernet. This happens at the local network level. There are many technical details: IEEE 802.11, radio frequency, channels, SSID, BSSID, MAC address, frames, access points, authentication, encryption, WPA2, WPA3.

Notice something important: IP address and MAC address are not the same thing.

ARP

Suppose your computer knows the router IP, such as 192.168.1.1, but not the router's MAC address. It asks: “Who has 192.168.1.1?” This is addressed through ARP (Address Resolution Protocol). 

Laptop: "Who has 192.168.1.1?"
Router: "That's me. My MAC is AA:BB:CC:DD:EE:FF"

IPv6 uses Neighbor Discovery Protocol (NDP) instead of ARP.

Level 5 — You leave your home: routers and the internet

Your router connects to an ISP such as Airtel, Jio, BSNL, ACT, and so on. Packets then travel through ISP core networks and internet routers. There is not one single internet router; there are millions of devices and links.

Routers

A router's basic job is: “Where should I send this packet next?” It uses routing information to choose the best next hop.

Destination       Next Hop
--------------------------------
10.0.0.0/8        Router A
20.0.0.0/8        Router B
142.250.0.0/16    Router C
0.0.0.0/0         Router D

Autonomous Systems and BGP

Large networks are grouped into Autonomous Systems (AS). The protocol used between autonomous systems is BGP (Border Gateway Protocol). It helps networks announce which IP prefixes they can reach.

Level 6 — DNS

Humans prefer names like youtube.com, while computers prefer IP addresses. DNS converts names into addresses. This is the internet’s phone book. 

youtube.com
      ↓
DNS
      ↓
142.xxx.xxx.xxx

DNS is hierarchical: root DNS servers, TLD servers such as .com, and authoritative DNS servers together map names to addresses. There are also caches in browsers, operating systems, routers, and ISPs to reduce latency.

DNS caching: your browser, OS, router, and ISP resolver can cache results so you do not hit the whole hierarchy every time.

Level 7 — HTTPS and TLS

Your browser needs a secure way to talk to the server. That is why we use HTTPS, which normally wraps HTTP with TLS. TLS provides encryption, authentication, and integrity.

Modern systems commonly use TLS 1.3.

Certificates

When you visit a site, the server presents a certificate that contains data about the domain, issuer, public key, validity, and signature. Your browser verifies the certificate using a trusted certificate chain. 

Certificate
-------------------------
Domain: example.com
Issuer: DigiCert
Public Key: ...
Validity: ...
Signature: ...

Public-key cryptography

Public-key cryptography uses a public key and a private key. The public key can be shared widely; the private key is kept secret by the server. This is the foundation of secure internet communication.

Level 8 — TCP, QUIC, and modern transport

Traditionally, web traffic used TCP as the transport protocol. TCP provides reliability by detecting missing packets and resending them. It also tracks sequence numbers, acknowledgements, flow control, congestion control, and connection state. 

Client                    Server
  SYN  ------------------>
       <------------------ SYN-ACK
  ACK  ------------------>

Modern traffic increasingly uses HTTP/3 on top of QUIC, which runs over UDP. QUIC provides streams, reliability, congestion control, connection migration, and encryption integrated through TLS. 

Application
    ↓
HTTP/3
    ↓
QUIC
    ↓
UDP
    ↓
IP

This is a major movement away from legacy HTTP/1.1 + TCP stacks, and it is increasingly important in modern web infrastructure.

Level 9 — OSI model and encapsulation

The common networking model is the OSI 7-layer model:

LayerName
7Application
6Presentation
5Session
4Transport
3Network
2Data Link
1Physical

In practice, engineers often use the simpler TCP/IP model:

Application
    ↓
Transport
    ↓
Internet
    ↓
Link

Each layer adds metadata around the data. This is called encapsulation. On the receiving side, the layers remove the labels in reverse order; that is called decapsulation.

Level 10 — Ports and HTTP

An IP address identifies a machine, but a computer needs a port to know which application should receive a packet. Example: 192.168.1.10:443. 

22   SSH
25   SMTP
53   DNS
80   HTTP
443  HTTPS
3306 MySQL
5432 PostgreSQL
6379 Redis
27017 MongoDB

HTTP is the application-layer protocol for web requests and responses. Common methods include GET, POST, PUT, PATCH, DELETE, HEAD, and OPTIONS.

GET /products HTTP/1.1
Host: example.com
Accept: application/json

Common status codes include 200 OK, 201 Created, 204 No Content, 301, 302, 304, 400, 401, 403, 404, 429, 500, 502, 503, and 504.

This reminds us that the application code is only one small piece of the whole journey. The actual internet path includes DNS, routing, TLS, load balancing, cache, storage, and infrastructure.

Level 12 — AWS and cloud infrastructure

In AWS, an application may sit behind Route 53, CloudFront, an Application Load Balancer, EC2/ECS/EKS, and a database service. 

Internet
   ↓
DNS (Route 53)
   ↓
CDN (CloudFront)
   ↓
Load Balancer (ALB)
   ↓

   ↓
MongoDB / PostgreSQL / Redis

This is the place where networking meets distributed systems: VPCs, subnets, route tables, security groups, NAT gateways, internet gateways, load balancers, and edge services become essential knowledge.

Level 13 — CDN, data centers, and load balancers

A Content Delivery Network stores copies of content near users so videos or assets do not always have to travel from the original server. Data centers house servers, switches, routers, storage, and network equipment. A load balancer distributes traffic so no single backend becomes overloaded. 

             Origin
              USA
               │
       ┌───────┼───────┐
       ↓       ↓       ↓
     India   Europe   Japan
      CDN      CDN      CDN

Level 14 — Caches and databases

If one million users request the same resource, it is wasteful to query the database each time. A cache such as Redis can serve repeated answers faster. Concepts include cache hit, cache miss, TTL, eviction, LRU, write-through, write-back, and cache invalidation. 

Client
  ↓
Application
  ↓
Redis
  ↓
Cache HIT

Databases add indexes, transactions, replication, sharding, WAL, B-trees, LSM trees, and connection pools.

Level 15 — Real end-to-end example

You type https://api.example.com/users/123.

  1. Browser parses the URL: scheme, host, and path.
  2. Browser asks DNS for the IP address.
  3. Computer determines the route via the routing table and gateway.
  4. Packets travel through Wi‑Fi, router, ISP, and internet infrastructure.
  5. The browser establishes a secure connection using TLS, often with QUIC or TCP.
  6. Browser sends an HTTP request.
  7. CDN or load balancer may handle the request.
  8. Backend service queries a database and returns a response.
  9. The response is sent back as packets and reconstructed in the browser.
HTTP/3 200
Content-Type: application/json

{
  "id": 123,
  "name": "Akash"
}

And all of this can happen in milliseconds.

Technology stack you need to eventually know

  • LEVEL 0: Computer fundamentals — binary, bits, bytes, CPU, RAM, storage, OS.
  • LEVEL 1: Networking fundamentals — IP, MAC, Ethernet, Wi‑Fi, ARP, ICMP, subnetting, CIDR, NAT, DHCP.
  • LEVEL 2: Routing — static routing, dynamic routing, OSPF, BGP, AS, Anycast.
  • LEVEL 3: Transport — TCP, UDP, QUIC, ports, sockets, handshakes, flow control, congestion control, retransmission.
  • LEVEL 4: DNS — resolver, root, TLD, authoritative DNS, A, AAAA, CNAME, MX, TXT, NS, TTL, DNSSEC, DoH, DoQ.
  • LEVEL 5: Security — TLS, TLS 1.2, TLS 1.3, certificates, CA, PKI, keys, hashing, signatures, mTLS.
  • LEVEL 6: Web — HTTP/1.1, HTTP/2, HTTP/3, REST, WebSockets, SSE, cookies, sessions, CORS, CSP, OAuth/OIDC.
  • LEVEL 7: Infrastructure — CDN, reverse proxy, load balancer, edge computing, caching.
  • LEVEL 8: Cloud — AWS, VPC, subnets, route tables, security groups, NACL, NAT Gateway, Internet Gateway, ALB, NLB, EC2, ECS, EKS, CloudFront.
  • LEVEL 9: Distributed systems — replication, sharding, leader election, consensus, CAP theorem, event-driven systems, message queues.
  • LEVEL 10: Production engineering — observability, logs, metrics, traces, SLIs, SLOs, incident management.

Current Internet topics to know in 2026

  • HTTP/3 — HTTP over QUIC.
  • QUIC — reliable multiplexed transport over UDP.
  • DNS over HTTPS (DoH) — DNS traffic over HTTPS/TLS.
  • DNS over QUIC (DoQ) — DNS over QUIC.
  • IPv6 — modern addressing and routing.
  • Encrypted DNS — DoT, DoH, DoQ.
  • HTTP/2 — streams, frames, multiplexing, HPACK.
  • TLS 1.3 — handshake, certificates, session resumption, 0-RTT.
  • Anycast — global routing for CDNs, DNS, and DDoS mitigation.
  • Edge computing — applications deployed near users.

Common missing basics

  • DHCP: automatically assigns IP addresses on a local network.
  • ICMP: used for ping, traceroute, and error reporting.
  • Subnetting and CIDR: how IP ranges are split and managed.
  • IPv6 and NAT64/DNS64: modern internet addressing.
  • Gateway and default route: how traffic leaves a local network.
  • Socket: the combination of IP and port used by an application.
  • Connection state: how protocols track sessions.
  • Flow control and congestion control: how networks avoid overload.
  • TTL: packet lifetime to prevent loops.
  • Reverse proxy and load balancing: route traffic to app servers.
  • Caching and invalidation: optimize repeated responses.
